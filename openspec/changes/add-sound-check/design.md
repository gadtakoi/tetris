# Design

## Context

Мотивация — в proposal.md, требования — в дельтах `sound-check` и `localization`.

**Как звучат звуки сейчас:**
- `synth.EFFECTS` синтезирует 8 эффектов, `music.render_music()` — мелодию, обе функции без pygame.
- `Audio.create()` открывает микшер 22 050 Гц, 16 бит, моно и превращает всё синтезированное в `pygame.mixer.Sound`: словарь эффектов по `input.Sound` (значения — имена из `synth.EFFECTS`) и одну мелодию. Канал 0 отведён под музыку.
- Каждый кадр `Audio.sync(controller)` проигрывает события кадра — каждое не больше одного раза — и ведёт музыку по `Controller.music_state`.
- Если микшер не открылся, `Audio.create()` возвращает `SilentAudio`.

**Запуск и цикл.** `cli.run()` разбирает аргументы (пока только `--max-frames`) и лишь потом импортирует `app`. `app.main()` открывает окно, создаёт `Controller` и `Audio` и крутит цикл:
1. события;
2. `controller.update(frame_ms)`;
3. `audio.sync()`;
4. `render.draw()`.

**Экраны на всё окно.** `layout` отдаёт надписи вида `ScreenText = (текст, позиция, роль, цвет)`, `render._draw_full_screen()` рисует их:
- роли `title`, `item` и `hint` — по центру позиции;
- роли `key` и `action` — от левого верхнего угла.

Шрифт подбирает `fitted_font()`: если надпись не помещается в ширину своей роли, берётся меньший размер.

**Замеры встроенного шрифта** (для раскладки ниже):
- 26 px: высота строки 19 px;
  - самая длинная строка списка — «12. Закрепление + конец игры», 253 px;
  - «неприятно» — 87 px;
  - самое длинное описание — «Клавиша удержана: 7 сдвигов от стены до стены», 422 px;
- 32 px: подсказка «Вверх / Вниз - выбор, Пробел - ещё раз» — 427 px;
- 56 px: «Проверка звуков» — 327 px.

**Автоповтор.** `menus.AUTOREPEAT["normal"] = (170, 50)`: первый повтор через 170 мс после нажатия, дальше каждые 50 мс. Нажатие даёт один сдвиг сразу. Если за один кадр набралось несколько сдвигов, звук move всё равно звучит один раз: события кадра хранятся без повторов.

## Goals / Non-Goals

**Goals:**
- Пункт проверки звучит так же, как в партии: те же объекты `pygame.mixer.Sound`, тот же микшер, отсчёт по кадрам. Сочетания и автоповтор не синтезируются отдельно, а собираются из звуков игры.
- Вся логика проверки (выбор, отметки, расписание звуков, отчёт) — без pygame и проверяется тестами напрямую, как `input.Controller`.
- Изменение не затрагивает партию: `Controller`, `Audio.sync()` и путь `app.main()` остаются прежними.

**Non-Goals:**
- Общий механизм «режимов» приложения: режим проверки — второй цикл в `app`, а не фаза `Controller`.
- Проверка звуков через тесты «на слух» (сравнение с эталоном): оценивает человек.

## Decisions

### Отдельный режим по параметру, а не пункт меню
`--sound-check` в `cli.py` вызывает `app.run_sound_check(max_frames)` вместо `app.main(max_frames)`.

Почему так:
- Режим нужен разработчику, игрок его не видит. Поэтому не меняются главное меню, инструкция F2 и `docs/user-guide.md`.
- Параметр работает и в exe, ведь `launcher.py` вызывает тот же `cli.run()`. Звуки можно проверить в том виде, в каком их слышит игрок exe.

Отвергнуто:
- Пункт меню или экран настроек: потребовал бы правил инструкции и меню ради инструмента разработки (выбор пользователя).
- Отдельный скрипт вне пакета: не попал бы в exe и дублировал бы открытие окна и микшера.

### Состояние проверки — `soundcheck.SoundCheck`, без pygame
Новый модуль `tetris_ui/soundcheck.py`:

```python
MUSIC = "music"  # cue of the background melody; other cues are synth.EFFECTS names

@dataclass(frozen=True)
class CheckItem:
    id: str                            # name in the report: "move", "move_repeat", ...
    title: str                         # English; tr() translates
    description: str                   # English; tr() translates
    cues: tuple[tuple[int, str], ...]  # (ms after the item starts, effect name or MUSIC)

ITEMS: tuple[CheckItem, ...]           # the 13 items of the spec table, in order

class CheckKey(Enum): UP, DOWN, PLAY, MARK, EXIT

@dataclass(frozen=True)
class Playback:
    stop: bool                         # stop everything before starting the cues
    cues: tuple[str, ...]              # cues that start in this frame

class SoundCheck:
    def __init__(self, can_play: bool = True,
                 on_report: Callable[[str], object] | None = None) -> None: ...
    index: int; marked: list[bool]; played: list[bool]; exit_requested: bool
    def key_down(self, key: CheckKey) -> None: ...
    def update(self, dt_ms: int) -> Playback: ...
    def report_json(self) -> str: ...
```

Задержки пункта 9 вычисляются из `menus.AUTOREPEAT["normal"]`: 0, затем 170 + 50·k для k = 0…5. Если пресет автоповтора поменяется, проверка пойдёт за ним. Тест сверяет результат с числами спецификации.

Почему не фаза `Controller`: `Controller` уже разбирает семь фаз и управляет партией. Проверке не нужны ни игра, ни настройки, ни музыка по фазам. Отдельный класс проще тестировать, и он не может сломать партию.

### Сочетания — расписание эффектов, а не заранее смешанный звук
Пункт — это список «через t мс начать эффект e». Одновременные звуки — несколько записей с t = 0, автоповтор — семь записей move.

Отвергнуто — заранее смикшировать сочетание в один буфер через `synth.mix()`:
- `mix()` обрезает сумму на 80 % шкалы, а микшер SDL складывает каналы до 100 %. Например, lock + game_over звучали бы не так, как в партии.
- Автоповтор в партии привязан к кадрам. Готовый буфер звучал бы ровнее, чем на деле.

### Отсчёт времени
`update(dt_ms)` вызывается раз в кадр с тем же `frame_ms`, что получает партия:
- если пункт в этом кадре начат (запуск, ↑, ↓, пробел, Enter), `Playback.stop = True`, а часы пункта остаются на 0. Кадр нажатия — это момент 0, и длинный первый кадр после синтеза не сдвигает расписание;
- иначе часы пункта растут на `dt_ms`.

Затем из ещё не начавшихся записей берутся те, чьё t не больше часов:
- каждый эффект — не больше одного раза за кадр, как в `Controller._sounds`;
- лишние записи того же эффекта отбрасываются, как лишние сдвиги в одном кадре партии.

Новый пункт или повтор заменяют список ожидающих записей. Поэтому хвост автоповтора прежнего проигрывания не звучит.

### Проигрывание: `Audio.play_check(playback)`
В `Audio` и `SilentAudio` добавляется метод `play_check(playback)`. У `SilentAudio` он ничего не делает. У `Audio`:
1. Если `playback.stop` — `pygame.mixer.stop()`: останавливаются все каналы, включая канал музыки.
2. Для каждой записи:
   - `MUSIC` — `channel.set_volume(DEFAULT_VOLUME / 100)` и `channel.play(music, loops=-1)` на канале 0;
   - эффект `e` — `effects[Sound(e)].set_volume(DEFAULT_SFX_VOLUME / 100)` и `play()`.

Громкость берётся из констант `settings`, а не из сохранённых настроек (требование «Проигрывание пунктов»). Громкость ставится при каждом запуске: объект `Sound` помнит громкость между проигрываниями, а проверка не должна зависеть от того, что было раньше.

`Audio.sync()` в режиме проверки не вызывается, поэтому его состояние музыки (`_generation`, `_paused`) не мешает.

### Отчёт
Отчёт готовит `SoundCheck.report_json()`:

```json
{
  "version": 1,
  "items": [
    {"number": 1, "id": "move", "played": true, "unpleasant": false},
    ...
  ]
}
```

- **Формат:** `json.dumps(..., indent=2)`, как `settings.json`. Файл легко прочитать и человеку, и Claude.
- **Когда пишется:**
  - `on_report(text)` вызывается один раз при создании `SoundCheck` — это новый отчёт, который перезаписывает прошлый;
  - затем после каждого изменения: пункт прозвучал впервые (только при `can_play`), отметка поставлена или снята.
- **Кто пишет:** `app` передаёт `lambda text: storage.save_sound_check(text, path)`. `storage` получает `SOUND_CHECK_FILE = "sound-check.json"`, `sound_check_path()` и `save_sound_check()` поверх готового `_write_atomic()`: атомарная запись, при ошибке предупреждение и `False` вместо исключения.
- **Где лежит:** в папке данных, а не в папке проекта. У exe папки проекта нет, а папка данных известна (`%APPDATA%\tetris`) и в тестах подменяется `TETRIS_DATA_DIR`.

Отвергнуто:
- Писать отчёт только при выходе: отметки пропали бы при аварийном закрытии окна.
- Markdown вместо JSON: его труднее проверять тестами, а читается JSON не хуже.

### Экран: `layout.sound_check_texts()` и общая отрисовка надписей
`layout.sound_check_texts(check, language, has_audio) -> list[ScreenText]` собирает надписи экрана. Новые роли:
- `row` и `mark` рисуются от левого верхнего угла, как `key` и `action`;
- `note` — по центру.

| Надпись | Роль | Позиция | Шрифт | Ширина | Цвет |
|---|---|---|---|---|---|
| «Sound check» | `title` | центр (260, 45) | 56 | 480 | `TEXT` |
| «<№>. <название>» | `row` | левый верх (40, 90 + 30·i) | 26 | 310 | `HIGHLIGHT` у выбранной, иначе `TEXT` |
| «unpleasant» | `mark` | левый верх (360, 90 + 30·i) | 26 | 140 | `MARK_COLOR` = (240, 96, 96) |
| описание | `note` | центр (260, 500) | 26 | 480 | `TEXT` |
| громкость или «No sound device» | `note` | центр (260, 528) | 26 | 480 | `VERSION_COLOR` |
| «Marks are saved to sound-check.json» | `note` | центр (260, 553) | 26 | 480 | `VERSION_COLOR` |
| две подсказки | `hint` | центр (260, 590) и (260, 616) | 32 | 480 | `TEXT` |

Последняя строка списка занимает y = 450…469, так что под описание остаётся место. По замерам всё помещается основным размером на обоих языках; подбор шрифта остаётся страховкой.

Отрисовка:
- `render.screen_font_size()` и `layout.screen_text_width()` узнают новые роли;
- из `_draw_full_screen()` выделяется `_draw_texts(surface, texts, fonts)`;
- `render.draw_sound_check(surface, check, language, has_audio, fonts)` заливает фон и вызывает `_draw_texts()`.

Строку громкости собирает шаблон `texts.check_volume_text(sfx, music, language)`, как `music_volume_text`. Проценты берутся из `settings.DEFAULT_SFX_VOLUME` и `settings.DEFAULT_VOLUME`, поэтому надпись не разойдётся с настоящей громкостью. Остальные надписи — постоянные строки в `texts.RU`.

### Язык и настройки
`run_sound_check()` один раз читает `storage.load_settings(storage.settings_path())` и берёт из настроек только `language`. Настройки не сохраняются, ведь режим их не меняет. `highscores.json` не читается.

### Клавиши
`app.SOUND_CHECK_KEYS: dict[int, CheckKey]`:
- `K_DOWN` → `DOWN`, `K_UP` → `UP`;
- `K_SPACE`, `K_RETURN`, `K_KP_ENTER` → `PLAY`;
- `K_x` → `MARK`;
- `K_ESCAPE` → `EXIT`.

Остальные клавиши не попадают в словарь и игнорируются.

Повтор клавиш pygame в игре не включён: удерживаемая клавиша даёт одно событие `KEYDOWN`, и в проверке так же. `pygame.QUIT` и `check.exit_requested` завершают цикл с кодом 0.

### Цикл `app.run_sound_check(max_frames)`
Цикл повторяет `main()`, но без `Controller` и текстового ввода:
1. `pygame.init()`, окно, шрифты, язык из настроек, `Audio.create()`.
2. `SoundCheck(can_play=audio.enabled, on_report=...)`.
3. Каждый кадр:
   - события → `key_down()`;
   - выход, если `exit_requested`;
   - `audio.play_check(check.update(frame_ms))`;
   - `render.draw_sound_check(...)` и `flip()`.
4. `finally: pygame.quit()`.

Общие части (окно, шрифты) уже вынесены в `create_window()` и `render.make_fonts()`, дублирования почти нет.

## Risks / Trade-offs

- [Громкость по умолчанию не совпадает с громкостью, которую игрок выставил себе] → Так задумано: оценивается то, что слышит новый игрок. Экран прямо показывает «effects 100%, music 50%». Если звук неприятен только на громкости игрока, он скажет об этом в чате.
- [Каждый запуск перезаписывает отчёт, прошлые отметки теряются] → Claude читает отчёт сразу после прослушивания (задача 5.2). Об этом написано на экране и в `docs/interface.md`.
- [Клавиша X в русской раскладке — «Ч»] → В партии X уже поворачивает фигуру через тот же `K_x`, так что проверка ведёт себя так же, как игра. Ручная проверка 4.2 включает нажатие X в русской раскладке.
- [Отсчёт по кадрам: звуки автоповтора сдвигаются до 1 кадра (≈17 мс)] → Так же звучит и партия. Для тестов время задаётся явно (`update(dt_ms)`), результат детерминирован.
- [Отметка одна, без причины] → Причину проще и точнее сказать словами в чате. Отчёт фиксирует, какие пункты отмечены, а обсуждение идёт по номерам пунктов.
- [Параметр `--sound-check` есть и у exe игрока] → Он безвреден: без параметра игра ведёт себя как раньше, а отчёт пишется только в папку данных.
