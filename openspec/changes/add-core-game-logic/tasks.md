# Tasks

## 1. Подготовка проекта

- [ ] 1.1 Создать `requirements.txt` с `pytest`, установить его в `.venv` и убедиться, что `.venv\Scripts\python -m pytest --version` выполняется без ошибок
- [ ] 1.2 Создать пакет `tetris/` (`__init__.py`) и каталог `tests/`; убедиться, что `python -m pytest` запускается и сообщает «no tests ran» без ошибок импорта

## 2. Фигуры (`tetris/pieces.py`)

- [ ] 2.1 Реализовать `PieceType` (I, O, T, S, Z, J, L), таблицу клеток ориентации 0 и размеры рамок по спецификации `tetrominoes`; вычисление ориентаций 1–3 формулой `(r, c) → (c, N−1−r)`; проверить тестом, что у каждой фигуры в каждой ориентации ровно 4 различные клетки
- [ ] 2.2 Написать тесты `tests/test_pieces.py` на сценарии «Форма T в исходной ориентации», «Поворот T/I по часовой», «Четыре поворота возвращают исходную форму», «Против часовой обратен по часовой», «O не меняется»; убедиться, что они проходят
- [ ] 2.3 Задать позиции появления (столбец 3; строка 1 для I, строка 2 для остальных) и проверить тестами клетки появления T, I и O из спецификации

## 3. Поле (`tetris/board.py`)

- [ ] 3.1 Реализовать `Board` 10×22 со скрытыми строками 0–1: `get(col, row)`, `is_free(col, row)` (за границами — несвободна), `place(cells, piece_type)`, `visible_rows()`; убедиться, что модуль импортируется
- [ ] 3.2 Написать тесты `tests/test_board.py` на все сценарии спецификации `playfield` (размеры, 220 пустых клеток, хранение типа, свободность, четыре клетки за границами, видимая часть — ровно строки 2–21); убедиться, что они проходят

## 4. Генератор (`tetris/randomizer.py`)

- [ ] 4.1 Реализовать `Randomizer`, принимающий `random.Random` и выдающий `PieceType` равновероятно; проверить тестами воспроизводимость по seed (100 фигур) и наличие всех 7 типов среди 700 фигур
- [ ] 4.2 Добавить в `tests/` вспомогательную заглушку RNG, выдающую заданную последовательность типов, и тест, что `Randomizer` с ней возвращает ровно эту последовательность

## 5. Игра и управление (`tetris/game.py`)

- [ ] 5.1 Реализовать `ActivePiece` (frozen dataclass: `type`, `rotation`, `col`, `row`, `cells()`) и `Game.new_game()`: пустое поле, активная и следующая фигуры, `is_over = False`; проверить тестами сценарии «Состояние новой партии» и «Перезапуск после конца игры»
- [ ] 5.2 Реализовать `move_left/right`, `rotate_cw/ccw` по схеме «попробовать и применить» с возвратом `bool`; проверить тестами сценарии сдвига (свободное поле, левая и правая стены, занятая клетка) и вращения (свободное поле, отказ у стены для вертикальной I, вращение I в скрытую зону)
- [ ] 5.3 Реализовать `step_down()` с результатом `StepResult` (`MOVED | LOCKED | REJECTED`) и `_lock()`/`_spawn()`: запись клеток в поле, следующая фигура становится активной, выбирается новая следующая; проверить тестами «Шаг вниз на свободном поле», «Фиксация на дне» (O в строках 20–21), «Фиксация на другой фигуре», «Следующая фигура становится текущей» (с заглушкой RNG)
- [ ] 5.4 Реализовать конец игры (block out) и отклонение всех команд после него; проверить тестами сценарии «Block out» и «Команды после конца игры» (поле не меняется, все команды возвращают отказ/`REJECTED`)
- [ ] 5.5 Добавить общий тест-свойство: на 20 seed выполнять по 500 случайных команд и после каждой проверять, что активная фигура (пока партия не окончена) находится в допустимом положении, а каждая строка поля содержит не больше 10 занятых клеток; убедиться, что тест проходит
