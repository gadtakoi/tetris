# Design

## Context

Мотивация описана в proposal.md, требования — в дельтах `game-screen`, `main-menu`, `localization`, `distribution`, `game-version`.

Название игры было записано в коде в трёх местах:
- `layout.TITLE` — заголовок окна, главного меню и списка клавиш;
- `cli.parse_args()` — `prog` и `description` справки;
- `build_exe.APP_NAME` — это и имя exe (`--name`), и название продукта в ресурсе версии.

**Сборка:**
- после успешной сборки `build_exe.py` удаляет `dist\tetris.exe` от самой первой сборки (`STALE_EXES`);
- PyInstaller кладёт файл сборки `<name>.spec` в корень проекта, а промежуточные файлы — в `build\<name>`; оба игнорируются git;
- `version_info.txt` хранится в git, его текст составляет `version_info_text()`, а тест сверяет файл с `__version__`.

**Данные игроков** лежат в `%APPDATA%\tetris` (`storage.data_dir()`); имя этой папки не связано с названием игры.

**Прежнее название встречалось** в тестах, документации, `openspec/config.yaml`, основных спецификациях, архиве OpenSpec и в сгенерированных файлах прежних сборок.

## Goals / Non-Goals

**Goals:**
- Одно место для названия игры, чтобы следующее переименование не требовало поиска по коду.
- Поиск прежнего названия по проекту (без учёта регистра, кроме `.git` и `.venv`) ничего не находит — ни в коде, ни в `openspec/`, ни в сгенерированных файлах.

**Non-Goals:**
- Совместимость со сборками под прежним названием: их файлы сборка не ищет и не удаляет.
- Переименование пакетов, папки данных и история git (см. «Вне рамок» в proposal.md).

## Decisions

### Название — `tetris_ui.GAME_TITLE`
`tetris_ui/__init__.py` рядом с `__version__` получает `GAME_TITLE = "Tetris Shmetris"`. Его используют:
- `layout.TITLE = GAME_TITLE` — окно, меню и список клавиш;
- `cli.parse_args()` — `prog=GAME_TITLE` и описание справки;
- `build_exe.py` — название продукта и описание файла в ресурсе версии.

Импорт `tetris_ui` не загружает pygame, поэтому `cli` по-прежнему разбирает аргументы до того, как pygame загрузится.

**Альтернатива — заменить строку в трёх местах, как было.** Отклонена: при следующем переименовании места снова пришлось бы искать, и одно из них легко пропустить.

### Имя файла — `build_exe.EXE_NAME = "tetris_shmetris"`
Имя exe отличается от названия игры (строчные буквы, подчёркивание, без пробела), поэтому это отдельная константа сборки.
- `--name EXE_NAME` даёт `dist\tetris_shmetris.exe`, `tetris_shmetris.spec` и `build\tetris_shmetris`.
- В ресурсе версии: `OriginalFilename` = «tetris_shmetris.exe», `InternalName` = «tetris_shmetris», `ProductName` и `FileDescription` = `GAME_TITLE`.
- Без пробела имя не нужно брать в кавычки в командах (например, `tetris_shmetris.exe --max-frames 30`).

### Без совместимости с прежним названием
Игрок решил, что совместимость со сборками под прежним названием не нужна. Поэтому:
- `STALE_EXES` по-прежнему содержит только `dist\tetris.exe` от самой первой сборки;
- файлы под прежним названием сборка не ищет и не удаляет;
- сгенерированные файлы прежних сборок (`build\<прежнее имя>`, кэш pytest, `__pycache__`) удаляются один раз вручную и создаются заново при следующих сборках и прогонах тестов.

### Прежнее название в тексте, спецификациях и архиве
- В тексте проекта прежнее название заменяется новым:
  - название игры — на «Tetris Shmetris»;
  - имя exe — на `tetris_shmetris.exe`;
  - файл сборки — на `tetris_shmetris.spec`.
- Замена затрагивает основные спецификации `openspec/specs/` и архив `openspec/changes/archive/`. Архив после этого читается так, будто игра всегда называлась «Tetris Shmetris». Это осознанная цена требования «ни одного упоминания».
- Основные спецификации получают новое название сразу, а не только при архивировании этого изменения. Дельты содержат тот же текст, поэтому архивирование ничего не испортит.
- Раздел Purpose спецификации `game-version` правится прямо в основной спецификации.
- `version_info.txt` пересоздаётся (`write_version_file()`) и коммитится вместе с изменением. Тест `test_committed_version_file_is_up_to_date` не даст о нём забыть.

## Risks / Trade-offs

- [Ярлыки и закрепления на exe с прежним именем перестанут работать] → старый файл остаётся там, где лежал, но устаревает. Игрок открывает новый `tetris_shmetris.exe`, его рекорды и настройки сохраняются в той же папке `%APPDATA%\tetris`.
- [В `dist\` может остаться exe под прежним именем] → совместимость не требуется. Такой файл удаляют вручную, сборка его не трогает.
- [Прежнее название останется где-то в проекте] → задача проверки ищет его по всему проекту, включая сгенерированные файлы. Тесты надписей и сборки сравнивают точные строки с новым названием.
- [История OpenSpec перестаёт отражать прежнее название] → по решению игрока. История git не переписывается.

## Migration Plan

При первой сборке появится `tetris_shmetris.exe`. Игроки открывают новый файл; их рекорды и настройки на месте. Для отката достаточно вернуть прежние `GAME_TITLE` и `EXE_NAME` и пересоздать `version_info.txt`.
