# Design

## Context

Шаг вниз и фиксация уже устроены как «попробовать и применить»: `_try(candidate)` меняет активную фигуру только при допустимом положении, `_lock()` выполняет последовательность фиксации, `_spawn()` сбрасывает таймер гравитации. Интерфейс получает команды через `Controller` и перечисление `Key`. Мотивация описана в proposal.md, требования — в дельтах `piece-control`, `controls` и `game-screen`.

## Goals / Non-Goals

**Goals:**
- Жёсткое падение и тень вычисляются одной функцией, поэтому тень всегда показывает ровно то место, где фигура зафиксируется.
- Жёсткое падение переиспользует `_lock()` без копирования правил фиксации.

**Non-Goals:**
- Кэширование положения тени. Тень пересчитывается каждый кадр: не больше 20 проверок по 4 клетки, это дёшево.

## Decisions

### `Game._dropped() -> ActivePiece`
Возвращает кандидата, опущенного построчно, пока следующее положение допустимо. Активную фигуру не меняет.
- `ghost_cells() -> tuple[Cell, ...]`: `()` после конца игры, иначе `self._dropped().cells()`.
- `hard_drop() -> StepResult`: `REJECTED` после конца игры, иначе `self.active = self._dropped()`, `self._lock()`, `LOCKED`.

Возврат `StepResult` согласован с `step_down()`: интерфейсу (и будущим звукам) не нужен новый тип. Альтернатива — возвращать число пройденных строк. Оно нужно только для очков за падение, а они вне рамок.

Таймер гравитации сбрасывается сам: `_lock()` вызывает `_spawn()`.

### Интерфейс
- `Key.HARD_DROP`, `KEY_MAP[pygame.K_SPACE] = Key.HARD_DROP`.
- `Controller.key_down(Key.HARD_DROP)` при `playing` вызывает `game.hard_drop()`. Повторителя нет, поэтому удержание не повторяет команду: pygame без `set_repeat` не шлёт повторных `KEYDOWN`.
- `render.draw` рисует тень после зафиксированных клеток и до активной фигуры: `layout.ghost_color(piece_type)` даёт `(r // 4, g // 4, b // 4)`. Клетки тени, совпадающие с активной фигурой, затем перекрываются ею, так что отдельной фильтрации не нужно.

### Тестовый сценарий «удержание пробела»
Для `Controller` удержание — это один `key_down`, затем кадры `update`, затем `key_up`. Тест проверяет, что за 1000 мс кадров вызван ровно один `hard_drop` (фиктивная игра в `tests/test_input.py` получает метод `hard_drop`).

## Risks / Trade-offs

- [Случайное нажатие Пробела сразу фиксирует фигуру без возможности отменить] → стандартное поведение hard drop. Lock delay вне рамок.
- [Тёмная тень (÷4) плохо видна на чёрном фоне для J (0, 0, 60)] → принятое упрощение. Цвет задан одной функцией `ghost_color`, его легко поменять.

## Migration Plan

Не требуется: API только расширяется.
