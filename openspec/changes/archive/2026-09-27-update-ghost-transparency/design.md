# Design

## Context

Тень рисует `render.draw` функцией `_fill_cell(surface, rect, layout.ghost_color(type))`. Эта функция заливает всю клетку 30 × 30 и обводит её контуром `CELL_OUTLINE` (20, 20, 20), поэтому линии сетки (40, 40, 48) под тенью пропадают. Линии сетки лежат на левой и верхней границе каждой клетки: вертикальные — при x = 20 + 30·c для c = 1…9, горизонтальные — при y = 20 + 30·k для k = 1…19. Мотивация описана в proposal.md, требование — в дельте `game-screen`.

## Goals / Non-Goals

**Goals:**
- Тень заметно бледнее и выглядит полупрозрачной, при этом цвета остаются точными, чтобы их можно было проверить тестом.

**Non-Goals:**
- Настоящее альфа-смешивание (`SRCALPHA`). Поле под тенью всегда пустое и чёрное, поэтому затемнение в 8 раз даёт тот же вид, но с точными значениями пикселей без округлений смешивания.

## Decisions

### Цвет: деление на 8
`layout.ghost_color()` возвращает `(r // 8, g // 8, b // 8)`, делитель задан константой `GHOST_DIVISOR = 8`. Для T это (20, 0, 30).

Альтернатива — альфа 1/8 поверх поля. Визуально то же на чёрном фоне, но значения пикселей зависят от формулы смешивания pygame, и тест пришлось бы писать с допуском.

### Заливка без контура с отступом 1 px
Для тени появляется функция `_fill_ghost(surface, rect, color)`, которая заливает прямоугольник `(x + 1, y + 1, 29, 29)`. Левая и верхняя линии клетки, то есть линии сетки, остаются видны. Правая и нижняя границы — это линии соседних клеток, заливка их тоже не задевает. Центр клетки (x + 15, y + 15) получает точный цвет тени. Для столбца 0 левая граница — край поля без линии сетки, там остаётся фон поля.

Альтернатива — перерисовывать сетку поверх тени. Это лишний проход, и так проще нечаянно зарисовать активную фигуру.

## Risks / Trade-offs

- [Тень J (0, 0, 30) на чёрном фоне едва видна] → это следствие выбранной прозрачности. Контур клеток тени образует сетка, и форма остаётся различимой. При необходимости делитель меняется одной константой.
