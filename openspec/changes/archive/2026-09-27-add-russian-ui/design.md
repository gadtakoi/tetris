# Design

## Context

После `add-main-menu` все надписи строит `tetris_ui/layout.py`: панель (`panel_texts`), наложения на поле (`overlay_lines`), экраны меню, настроек, рекордов и списка клавиш. Строки задаются там же или в `tetris_ui/menus.py` и `layout.HOTKEYS`. Язык хранится в `Settings.language` («en» или «ru»), но пока ни на что не влияет. `render.py` рисует надписи тремя шрифтами фиксированного размера (`small` 32, `big` 56, `table` 26). Замеры: «ИГРА ОКОНЧЕНА» шрифтом 56 px — 333 px при ширине поля 300; «ГРОМКОСТЬ 100%» шрифтом 32 px — 203 px при ширине панели 180. Мотивация описана в proposal.md, требования — в `specs/localization`.

## Goals / Non-Goals

**Goals:**
- Одна таблица перевода, совпадающая с таблицей спецификации и проверяемая тестом построчно.
- Ни одна надпись ни на каком языке не выходит за свою область, без ручного подбора сокращений.

**Non-Goals:**
- Общая система локализации (gettext, файлы .po): языков два, таблица небольшая.

## Decisions

### `tetris_ui/texts.py` (без pygame)
```python
RU: dict[str, str] = {"NEXT": "ДАЛЕЕ", ..., "Select / new game": "Выбор / новая игра"}

def tr(text: str, language: str) -> str         # перевод или сам текст
def music_volume_text(volume, language)          # "MUSIC 50%" / "МУЗЫКА 50%"
def sound_volume_text(volume, language)          # "SOUND 100%" / "ЗВУК 100%"
def name_line(name, language)                    # "Name: Ann_" / "Имя: Ann_"
```
Ключи — английские строки: они же записаны в спецификациях, поэтому английский язык — это тождественное отображение, и существующие тесты с английскими ожиданиями не меняются. Шаблоны с числами и именами — отдельные функции, в словарь попадают только постоянные строки. Строка настройки собирается как `f"{tr(label)}: {tr(value)}"`, и числа с процентами проходят через `tr` без изменений.

Альтернатива — символьные ключи (`"panel.next"`). Надёжнее при правке английского текста, но тогда английский тоже нужно вести таблицей, а тексты спецификаций перестают совпадать с кодом один к одному.

### Перевод в `layout.py`
Каждая функция, возвращающая надписи, берёт `language = controller.settings.language` и пропускает постоянные строки через `tr`. Не переводятся `TITLE`, имена, числа и названия языков: в таблице их нет, а `tr` возвращает строку без изменений. Для проверки полноты `layout` получает функцию `all_screen_texts(controller)`: она собирает надписи всех экранов для текущих настроек, и тест прогоняет её на обоих языках.

### Подбор размера шрифта (`render.py`)
```python
def fitted_font(fonts, base_size, text, max_width) -> pygame.font.Font
```
Сначала пробуется базовый размер, затем размеры с шагом 2 px вниз, пока надпись не поместится или не будет достигнут минимум 14 px. Шрифты кэшируются по размеру в `Fonts`. Ширина области задаётся каждой функции отрисовки:

| Область | Ширина |
|---|---|
| панель | `WINDOW_W − PANEL_X` = 180 px |
| наложения на поле | `FIELD_W` = 300 px |
| экраны меню | окно без полей по 20 px, 480 px |
| столбец клавиш | 190 px (от x = 70 до 260) |
| столбец действий | 240 px (от x = 270 до 510) |

Английские надписи и сейчас помещаются основным размером, поэтому для них ничего не меняется.

## Risks / Trade-offs

- [Шрифт меньше основного выглядит неровно рядом с соседними строками] → уменьшаются только не помещающиеся надписи, остальные остаются основного размера. Тест проверяет, что уменьшение не опускается ниже 14 px.
- [Новые надписи в будущих изменениях могут остаться без перевода] → тест полноты на русском языке: на всех экранах не остаётся строк, совпадающих с английскими ключами таблицы.

## Migration Plan

Не требуется: язык по умолчанию английский, поле `language` уже хранится.
