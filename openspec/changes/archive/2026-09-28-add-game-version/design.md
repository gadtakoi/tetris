# Design

## Context

Мотивация описана в proposal.md, требования — в `specs/game-version`.

- **Сборка exe.** `build_exe.py` вызывает PyInstaller (≥ 6.16) списком аргументов командной строки. Файл `.spec` каждый раз создаётся заново, а промежуточные файлы попадают в `build/`.
- **Пакет `tetris_ui`.** Его `__init__.py` сейчас содержит только docstring. Импорт `tetris_ui` не тянет pygame: pygame импортируют только модули `app`, `render` и `audio`.
- **Главное меню.** Его рисует `render._draw_full_screen()` по надписям `layout.full_screen_texts()`: заголовок при y = 120, пункты с y = 240, подсказка при y = 590. После `add-in-game-guide` пунктов шесть, последний при y = 490.
- **Проверки.** Сборочный тест (`TETRIS_BUILD_TEST=1`) собирает exe и запускает его без экрана.

## Goals / Non-Goals

**Goals:**
- Номер версии записан в одном месте. Меню и exe берут его оттуда, поэтому разойтись не могут.
- Ресурс версии exe проверяется автоматически, а не только глазами в проводнике.

**Non-Goals:**
- Правила выпуска и хранение истории версий: достаточно правила в `docs/build.md`.

## Decisions

### Единственный источник — `tetris_ui.__version__`
`tetris_ui/__init__.py` получает `__version__ = "1.0.0"`:
- `layout` импортирует его для надписи в меню;
- `build_exe.py` импортирует его для ресурса exe — pygame при этом не загружается;
- в exe константа попадает вместе с кодом, и отдельные файлы данных не нужны.

**Отклонённые альтернативы:**
- **Файл `VERSION` в корне проекта.** Его пришлось бы добавлять в exe (`--add-data`) и читать при запуске.
- **`importlib.metadata`.** Проект не устанавливается через pip, поэтому метаданных пакета нет.
- **`tetris/__init__.py`.** Версия — свойство программы целиком, а пакет логики ничего не знает о поставке.

### Надпись в меню
- `layout.VERSION_TEXT = f"v{__version__}"`, цвет `layout.VERSION_COLOR = (130, 130, 140)`.
- `full_screen_texts()` добавляет её только для экрана `menu`, последней, с новой ролью `version` и позицией (510, 630) — правым нижним углом надписи.
- `render` рисует роль `version` шрифтом 20 px (`screen_font_size("version")`) по `bottomright`. Надпись высотой около 13 px занимает y ≈ 617…630, а подсказка меню заканчивается при y ≈ 601, так что они не пересекаются.
- Номер не переводится: в таблице `RU` его нет, и `tr` вернул бы его без изменений. Поэтому `layout` не пропускает надпись через перевод.

### Ресурс версии exe — `version_info.txt` в git и `--version-file`
- `build_exe.py` получает чистую функцию `version_info_text(version: str) -> str`. Она возвращает текст `VSVersionInfo` в формате, который принимает PyInstaller:
  - `filevers` и `prodvers` = `(MAJOR, MINOR, PATCH, 0)`;
  - `StringTable("040904B0", …)` с полями `FileVersion` («1.0.0.0»), `ProductVersion` («1.0.0»), `ProductName` и `FileDescription` («SEVA Tetris»), `OriginalFilename` («SEVA Tetris.exe») и `InternalName`;
  - `VarFileInfo` с `Translation` `[1033, 1200]`.
- Текст хранится в `version_info.txt` в корне проекта, и этот файл хранится в git. Так данные ресурса версии видны в репозитории и в его истории.
- Перед каждой сборкой `main()` заново создаёт файл из `__version__`, но записывает его, только если текст изменился. PyInstaller получает его через `--version-file`.
  - Так exe всегда соответствует коду, даже если после повышения номера файл не обновили вручную.
  - Номер по-прежнему задаётся в одном месте, а файл только выводится из него.
- Обычный тест сравнивает файл в репозитории с `version_info_text(__version__)` и проверяет, что git его не игнорирует. Если номер подняли, а файл не обновили, тест это покажет. Исправление — запустить сборку и закоммитить обновлённый файл.
- Юнит-тест проверяет текст функции без сборки. Сборочный тест читает свойства готового exe через PowerShell: `(Get-Item -LiteralPath <exe>).VersionInfo`, поля `FileVersion`, `ProductVersion`, `ProductName`, `OriginalFilename`.

**Отклонённые альтернативы:**
- **Файл в `build/`.** Эта папка исключена из git (`.gitignore`), а файл версии должен быть в репозитории.
- **`version_info.txt`, который правят вручную.** Номер пришлось бы менять в двух местах.
- **Правка `.spec`-файла.** Сборка создаёт его заново при каждом запуске.
- **Чтение ресурса через `ctypes` и `version.dll`.** Кода больше, чем у вызова PowerShell. PowerShell есть в каждой Windows 10/11, а сборочный тест и так работает только на Windows.

## Risks / Trade-offs

- [Номер подняли, но закоммитили старый `version_info.txt`] → обычный тест сравнивает файл с `version_info_text(__version__)`. Сборка всё равно записывает актуальный файл.
- [Номер забудут поднять перед новой сборкой] → в `docs/build.md` описано, когда и какую цифру менять. Номер задан в одном месте, поэтому меню и exe всё равно совпадут.
- [Надпись шрифтом 20 px плохо читается] → это второстепенная информация. Цвет приглушён, чтобы надпись не спорила с пунктами меню; тест проверяет, что она целиком в окне.
- [PyInstaller изменит формат файла версии] → сборочный тест сразу покажет пустые свойства exe. Формат `VSVersionInfo` стабилен во всех версиях PyInstaller 6.

## Migration Plan

Не требуется: данные игры не меняются, ресурс версии появляется при следующей сборке.
