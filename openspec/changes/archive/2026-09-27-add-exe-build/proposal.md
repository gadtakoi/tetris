# Proposal

## Why

Сейчас для запуска игры нужны установленный Python, виртуальное окружение с зависимостями и команда `python -m tetris_ui`. Поделиться игрой с человеком без Python нельзя. Один файл `tetris.exe`, который запускается двойным щелчком, снимает это ограничение для Windows.

## What Changes

- Команда сборки `python build_exe.py` (из `.venv` с зависимостями из `requirements-build.txt`) создаёт один файл `dist\tetris.exe` через PyInstaller в режиме `--onefile --windowed`: без окна консоли и без файлов рядом.
- Exe запускается двойным щелчком на Windows 10/11 x64 без установленного Python и даёт ту же игру, что `python -m tetris_ui`, со всеми реализованными к моменту сборки возможностями. Рекорды пишутся в `%APPDATA%\tetris\`, а не рядом с exe.
- Точка входа принимает необязательный параметр командной строки `--max-frames N`: игра завершается с кодом 0 после N кадров. Он нужен для автоматической проверки собранного exe и одинаково работает в `python -m tetris_ui`.
- Вывод предупреждений в stderr становится безопасным для оконного exe, где `sys.stderr` может быть `None`.
- `requirements-build.txt` с PyInstaller отделён от `requirements.txt`, чтобы тяжёлый сборщик не был нужен для игры и тестов.

## Вне рамок

- Иконка приложения, сведения о версии в свойствах файла, цифровая подпись.
- Установщик, ярлыки, автообновление.
- Сборки для macOS и Linux, 32-битная Windows.
- Борьба с ложными срабатываниями антивирусов, кроме рекомендаций в design.md.

## Capabilities

### New Capabilities
- `distribution`: команда сборки и её результат, запуск exe без Python, автономность (без внешних файлов, данные в профиле пользователя), параметр `--max-frames` для автоматической проверки.

### Modified Capabilities
<!-- Нет: поведение игры не меняется. `--max-frames` описан в `distribution`. -->

## Impact

- Новые файлы:
  - `build_exe.py`: вызов PyInstaller;
  - `launcher.py`: точка входа exe;
  - `requirements-build.txt`;
  - `tetris_ui/cli.py`: разбор аргументов и запуск.
- `tetris_ui/__main__.py` переходит на `cli.run()`. Функции, пишущие в stderr (например, `storage.save` из `add-high-scores`), используют безопасный вывод.
- `.gitignore` уже содержит `build/`, `dist/`, `*.spec`.
- Тесты: быстрый `tests/test_cli.py` и медленный `tests/test_build.py`, который собирает и запускает exe только при `TETRIS_BUILD_TEST=1`.
- Изменение стоит реализовать последним из четырёх запланированных (hard drop и тень, рекорды, звук, exe), чтобы exe содержал все возможности. Технически оно от них не зависит.
