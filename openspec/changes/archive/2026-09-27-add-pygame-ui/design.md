# Design

## Context

Логика в пакете `tetris/` полностью готова и не зависит от pygame. Интерфейсу доступно такое API `Game`:
- команды: `move_left/right`, `rotate_cw/ccw`, `step_down`, `tick(dt_ms)`, `new_game()`;
- состояние: `board` (`get`, `visible_rows`), `active` (`cells()`, `type`), `next_type`, `score`, `lines`, `level`, `is_over`.

Тест `tests/test_architecture.py` импортирует каждый модуль из `tetris.__path__` и проверяет, что pygame не загружен. Поэтому код, импортирующий pygame, не может лежать внутри `tetris/`. Python в `.venv` — 3.14.3, на PyPI для него есть pygame-ce 2.5.8, но наличие колеса для Windows под cp314 проверяется только установкой. Мотивация описана в proposal.md, требования — в `specs/controls` и `specs/game-screen`.

## Goals / Non-Goals

**Goals:**
- Правила ввода (автоповтор, пауза, перезапуск, ограничение времени кадра) проверяются pytest без окна и без pygame.
- Отрисовка проверяется автоматически в headless-режиме (`SDL_VIDEODRIVER=dummy`) по цветам пикселей и списку выведенных надписей.
- `tetris/` не меняется.

**Non-Goals:**
- Абстракция над библиотекой отрисовки (возможность заменить pygame).
- Оптимизация отрисовки (грязные прямоугольники и т. п.): кадр перерисовывается целиком, для 200 клеток это дёшево.

## Decisions

### Пакет `tetris_ui/` рядом с `tetris/`
```
tetris_ui/
  __init__.py
  __main__.py   # python -m tetris_ui → main()
  input.py      # без pygame: Key, KeyRepeater, Controller
  layout.py     # без pygame: константы раскладки, цвета, cell_rect(), screen_texts()
  render.py     # pygame: draw(surface, controller, fonts)
  app.py        # pygame: окно, цикл событий, перевод pygame-клавиш в Key
tests/
  test_input.py       # Controller и KeyRepeater с фиктивной Game-подобной записью команд
  test_ui_smoke.py    # render/app с SDL_VIDEODRIVER=dummy
```
Отдельный пакет сохраняет тест архитектуры без изменений: `tetris/` по-прежнему гарантированно без pygame. Альтернатива — `tetris/ui/` с исключением в тесте архитектуры. Она ослабляет автоматическую проверку и путает, что считается «логикой».

### Контроллер без pygame (`input.py`)
- `Key` — собственное перечисление: `LEFT, RIGHT, DOWN, ROTATE_CW, ROTATE_CCW, PAUSE, RESTART`. Перевод pygame-клавиш в `Key` делается одной таблицей в `app.py`, где несколько клавиш могут вести к одному `Key` (↑ и X → `ROTATE_CW`).
- `Controller(game)` хранит `paused` и повторители, методы:
  - `key_down(key)`, `key_up(key)`;
  - `update(frame_ms)`: сначала повторы по удержанию, затем `game.tick(min(frame_ms, 100))`, если не пауза и не конец игры.
- `KeyRepeater(delay_ms, interval_ms)` для сдвига (170/50) и для мягкого падения (0/50). `press()` возвращает немедленное срабатывание. `update(dt)` возвращает число повторов за `dt` (может быть больше 1), `release()` сбрасывает состояние.
- Горизонталь — один повторитель с текущим направлением: нажатие ← или → меняет направление и перезапускает его, отпускание текущего направления останавливает его. Так реализуется правило «последняя нажатая побеждает».

Контроллеру достаточно объекта с методами `Game`, поэтому тесты передают туда настоящий `Game` или запись вызовов. Альтернатива — встроенный повтор клавиш pygame (`pygame.key.set_repeat`). Он одинаков для всех клавиш (у мягкого падения нужна нулевая задержка), зависит от ОС и не тестируется без окна.

### Порядок в кадре
`events → controller.key_down/key_up → controller.update(frame_ms) → render.draw → display.flip`, где `frame_ms = clock.tick(60)`. Команды игрока применяются до гравитации того же кадра. Так мягкое падение, сбрасывающее таймер гравитации, не даёт двойного шага.

### Раскладка и цвета в `layout.py` без pygame
Константы: окно 520×640, `CELL = 30`, поле с (20, 20) размером 300×600, панель с x = 340, превью с (340, 60) размером 4×4 клетки, текст счётчиков с y = 220. Цвета фигур — словарь `PieceType → (r, g, b)` по спецификации, фон окна (24, 24, 32), фон поля (0, 0, 0), сетка (40, 40, 48), рамка (200, 200, 200).

Там же `screen_texts(controller) -> list[str]` возвращает надписи, которые должны быть на экране: `NEXT, SCORE, <score>, LINES, <lines>, LEVEL, <level>` и при необходимости `PAUSE` или `GAME OVER, Press Enter`. `render.draw` выводит ровно эти строки. Так тесты проверяют надписи списком строк, а не распознаванием текста на пикселях.

### Рисование клеток
Клетка — заливка цветом фигуры на всю клетку и тонкий тёмный контур на 1 px по краю. Центр клетки всегда имеет чистый цвет фигуры, что проверяет дымовой тест. Затемнение для паузы и конца игры — полупрозрачная поверхность (альфа 160) только над полем, текст по центру поля. Шрифт — встроенный шрифт pygame-ce (`pygame.font.Font(None, size)`), он не требует системных шрифтов.

### Дымовой тест
`tests/test_ui_smoke.py` в начале выставляет `os.environ["SDL_VIDEODRIVER"] = "dummy"` и `SDL_AUDIODRIVER = "dummy"`, пропускается через `pytest.importorskip("pygame")`, рисует на `pygame.Surface((520, 640))` и проверяет пиксели и `screen_texts`. Запуск окна проверяется вызовом `app.main(max_frames=N)`, где параметр `max_frames` существует только для тестов, с последующей проверкой размера и заголовка окна.

## Risks / Trade-offs

- [Нет колеса pygame-ce под cp314 для Windows, и сборка из исходников не пройдёт] → задача 1.1 проверяет установку первой. Если она не удалась, пересоздаём `.venv` на Python 3.13 (логика от версии не зависит) и фиксируем это в `requirements.txt` комментарием.
- [Повторы квантуются кадрами: при 60 FPS срабатывание в «170 мс» происходит на ближайшем кадре] → повторитель считает время точно и за длинный кадр выдаёт несколько повторов, поэтому средняя частота верна. Разница меньше одного кадра незаметна.
- [Ограничение кадра 100 мс замедляет игру при стабильно низком FPS (< 10)] → на поле 10×20 это нереалистично. Ограничение защищает от провала фигуры после перетаскивания окна.
- [Шрифт по умолчанию отличается между версиями pygame-ce] → тесты не проверяют пиксели текста, только список надписей.

## Migration Plan

Не требуется: добавляется новый пакет и зависимость. Для отката достаточно удалить `tetris_ui/` и строку `pygame-ce` из `requirements.txt`.
