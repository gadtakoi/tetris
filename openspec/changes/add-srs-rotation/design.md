# Design

## Context

`Game._rotate(delta)` строит кандидата со следующей ориентацией на том же месте и принимает его через `_try()`. Ориентации всех фигур вычисляются в `tetris/pieces.py` поворотом клеток внутри рамки (3 × 3, у I и O — 4 × 4) и уже совпадают с базовыми состояниями SRS. Это проверено: исходные положения и сценарии отскоков дельты посчитаны на настоящих формах из кода. Мотивация описана в proposal.md, требование — в дельте `piece-control`.

## Goals / Non-Goals

**Goals:**
- Таблицы SRS в одном месте, в виде данных, проверяемых тестом.
- Поворот остаётся одной «атомарной» командой: либо фигура целиком встаёт в новое положение, либо ничего не меняется.

**Non-Goals:**
- Распознавание T-spin: это уже правило очков (вне рамок).

## Decisions

### Таблицы в `tetris/pieces.py`
```python
# (from_rotation, to_rotation) -> четыре смещения (dx, dy), dy вверх — как в SRS
_JLSTZ_KICKS: dict[tuple[int, int], tuple[tuple[int, int], ...]] = {...}
_I_KICKS: dict[tuple[int, int], tuple[tuple[int, int], ...]] = {...}

def kick_offsets(piece_type, from_rotation, to_rotation) -> tuple[tuple[int, int], ...]:
    """(0, 0) и затем четыре смещения SRS; для O только (0, 0)."""
```
Таблицы записаны в системе SRS (y вверх), как в спецификации и во всех справочниках, а в координаты поля их переводит `Game._rotate`: `col + dx`, `row - dy`. Так таблицы можно сверять с источниками построчно.

Альтернатива — хранить уже перевёрнутые dy. Их невозможно сверить с таблицами из справочников без пересчёта в уме.

### Перебор в `Game._rotate`
```python
for dx, dy in kick_offsets(type, rotation, target):
    if self._try(replace(active, rotation=target, col=col + dx, row=row - dy)):
        return True
return False
```
`_try` уже проверяет допустимость и конец игры, поэтому отказ ничего не меняет.

### Проверка таблиц тестом
- Для каждого перехода первым идёт (0, 0), затем ровно четыре смещения.
- Обратный переход — те же смещения с обратным знаком: это свойство SRS проверено при подготовке и ловит опечатки в таблицах.
- Сценарии дельты проверяются на настоящей игре.

## Risks / Trade-offs

- [Отскоки вверх позволяют «поднимать» фигуру поворотами у пола и тянуть время] → без задержки фиксации фигура на полу фиксируется на следующем шаге гравитации. С `add-lock-delay` число продлений ограничено 15.
- [Игроки NES-тетриса могут счесть отскоки непривычными] → это стандарт современных тетрисов, который попросил игрок. Выбор системы поворотов вне рамок.
