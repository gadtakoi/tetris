# Spec Delta

## ADDED Requirements

### Requirement: ID установки
Игра SHALL хранить ID установки в файле `install-id` в той же папке, что и `highscores.json`. ID SHALL состоять ровно из 32 символов `0-9a-f` в нижнем регистре. Файл может заканчиваться переводом строки. Если файла нет или его содержимое не является таким ID, игра SHALL при запуске создать новый случайный ID (не менее 128 бит случайности) и записать его в файл атомарно. Если записать файл не удалось, игра SHALL NOT прерываться с ошибкой и SHALL использовать новый ID до конца сеанса. Режим проверки звуков SHALL NOT создавать `install-id`.

#### Scenario: Первый запуск
- **WHEN** в папке данных нет файла `install-id`, и запускается игра
- **THEN** появляется файл `install-id` с 32 символами из `0-9a-f`

#### Scenario: Повторный запуск
- **WHEN** в файле `install-id` записано `0123456789abcdef0123456789abcdef`, и запускается игра
- **THEN** игра использует этот ID, и файл не меняется

#### Scenario: Испорченный ID
- **WHEN** файл `install-id` содержит текст «hello»
- **THEN** игра записывает в файл новый ID из 32 символов `0-9a-f`

### Requirement: Подпись таблицы
Начиная с этого изменения, `highscores.json` SHALL содержать JSON-объект `{"version": 2, "entries": [...], "sig": "..."}`. Поле `entries` устроено как прежде: записи с полями `name`, `score`, `lines`, `level`. Поле `sig` SHALL быть подписью HMAC-SHA256 из 64 символов `0-9a-f` в нижнем регистре. Подпись SHALL вычисляться секретным ключом игры по данным, которые однозначно включают номер формата 2, ID установки и все записи `entries` со всеми полями в порядке файла. Изменение любого из них SHALL менять подпись. Подпись SHALL NOT зависеть от пробелов, отступов и порядка ключей внутри объектов в файле.

#### Scenario: Сохранение и загрузка подписанной таблицы
- **WHEN** в таблицу добавлен результат «Иван», 1200 очков, 13 линий, уровень 1, и игра той же установки запускается снова
- **THEN** загруженная таблица содержит эту запись с теми же значениями

#### Scenario: Формат файла
- **WHEN** таблица сохранена
- **THEN** файл содержит `"version": 2`, список `entries` и поле `sig` из 64 символов `0-9a-f`

#### Scenario: Переформатирование файла
- **WHEN** сохранённый файл переписан с другими отступами и другим порядком ключей, но с теми же значениями
- **THEN** таблица загружается полностью

### Requirement: Неподтверждённая таблица
Игра SHALL начинать с пустой таблицы, если `highscores.json` — корректный JSON-объект, но любое из условий выполнено: `version` не равно 2; поля `sig` нет или это не строка; `sig` не совпадает с подписью, вычисленной для текущего ID установки. Сравнение подписей SHALL выполняться за время, не зависящее от места первого расхождения. В этом случае игра SHALL выводить предупреждение в консоль, SHALL NOT прерываться с ошибкой и SHALL NOT менять файл до первого сохранения таблицы. Корректные записи SHALL загружаться только из файла с верной подписью.

#### Scenario: Правка очков вручную
- **WHEN** в сохранённом файле очки 1200 заменены на 999999, а `sig` не изменён
- **THEN** загружается пустая таблица, игра запускается

#### Scenario: Файл с другой установки
- **WHEN** `highscores.json`, сохранённый при ID `0123456789abcdef0123456789abcdef`, загружается при ID `fedcba9876543210fedcba9876543210`
- **THEN** загружается пустая таблица

#### Scenario: Файл прежнего формата
- **WHEN** файл содержит `{"version": 1, "entries": [{"name": "A", "score": 100, "lines": 1, "level": 0}]}`
- **THEN** загружается пустая таблица

#### Scenario: Подпись удалена
- **WHEN** из сохранённого файла удалено поле `sig`
- **THEN** загружается пустая таблица

#### Scenario: Новый рекорд после подделки
- **WHEN** загружена пустая таблица из-за неверной подписи, и партия окончена с 500 очками
- **THEN** файл перезаписывается таблицей из одной записи с верной подписью

#### Scenario: Потерянный ID установки
- **WHEN** таблица сохранена, файл `install-id` удалён, и игра запускается снова
- **THEN** создаётся новый ID, и загружается пустая таблица

## MODIFIED Requirements

### Requirement: Хранение таблицы
Таблица SHALL храниться в файле `highscores.json` в папке `tetris_shmetris` внутри папки данных пользователя: `%APPDATA%` на Windows, `~/.local/share` на других ОС. Файл SHALL быть в кодировке UTF-8 и содержать JSON-объект `{"version": 2, "entries": [...], "sig": "..."}` в формате из требования «Подпись таблицы», где каждая запись — объект с полями `name` (строка), `score`, `lines`, `level` (неотрицательные целые). Таблица SHALL сохраняться сразу после добавления новой записи; запись файла SHALL быть атомарной (через временный файл), чтобы прерванное сохранение не портило прежнюю таблицу. Прежнюю папку `tetris` (`%APPDATA%\tetris`) игра SHALL NOT читать, изменять и удалять.

#### Scenario: Сохранение и загрузка
- **WHEN** в таблицу добавлен результат «Иван», 1200 очков, 13 линий, уровень 1, и игра запускается снова
- **THEN** загруженная таблица содержит эту запись с теми же значениями

#### Scenario: Первый запуск
- **WHEN** файла `highscores.json` нет
- **THEN** таблица пустая, и файл создаётся (вместе с папкой) при первом сохранении

#### Scenario: Папка данных
- **WHEN** `%APPDATA%` — это `C:\Users\Player\AppData\Roaming`, и сохраняется рекорд
- **THEN** таблица записана в `C:\Users\Player\AppData\Roaming\tetris_shmetris\highscores.json`

#### Scenario: Прежняя папка не читается
- **WHEN** в `%APPDATA%\tetris` лежит `highscores.json` с записями, в `%APPDATA%\tetris_shmetris` этого файла нет, и игра запускается
- **THEN** таблица пустая, а `%APPDATA%\tetris\highscores.json` не изменён
