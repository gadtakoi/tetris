# Версия и CHANGELOG

Задача скилла: после каждой новой возможности или заметного изменения **спросить игрока**, поднимать ли версию, и записать изменение в `CHANGELOG.md`. Решает игрок. Без его ответа ничего не менять.

## 1. Понять, что изменилось

- Взять изменения с прошлой записи в `CHANGELOG.md`. Если файла нет, взять изменения с последнего изменения номера версии:
  - `git log --oneline` и `git diff`, включая незакоммиченные изменения;
  - `proposal.md` активного OpenSpec-изменения или изменений, архивированных с тех пор, в `openspec/changes/archive/`.
- Если изменение уже есть в `CHANGELOG.md` (в разделе версии или «Не выпущено»), ещё раз не спрашивать. Сказать одной строкой, что запись уже есть.
- Если изменилось только внутреннее устройство (рефакторинг, тесты, документация разработчика), игрок этого не заметит. Не спрашивать и завершить скилл.

## 2. Предложить цифру по правилам `docs/build.md`

Текущая версия — `__version__` в `tetris_ui/__init__.py`.

- **PATCH** (x.y.Z): только исправления ошибок.
- **MINOR** (x.Y.0): новые возможности, а прежние рекорды и настройки читаются как раньше.
- **MAJOR** (X.0.0): несовместимые изменения. Например, новый формат `highscores.json` или `settings.json`, который старые версии не прочитают, или потеря прежних данных после обновления.

Если в «Не выпущено» уже что-то накоплено, цифру выбирать по самому сильному изменению среди накопленного и нового.

## 3. Спросить

Задать один вопрос через AskUserQuestion. В вопросе перечислить изменения, которые попадут в запись. Варианты:

1. «Поднять до <новая версия> (Recommended)»: цифра из шага 2, в описании — почему именно она.
2. Другая осмысленная цифра, например MINOR вместо MAJOR, с новой версией в названии.
3. «Только CHANGELOG, без версии»: запись в раздел «Не выпущено». Версию поднимут перед сборкой для игроков, как советует `docs/build.md`.
4. «Пропустить»: ничего не менять.

## 4. Выполнить ответ

### Запись в CHANGELOG.md

Файл лежит в корне проекта. Если его нет, создать с шапкой:

```markdown
# Журнал изменений

Заметные изменения Tetris Shmetris. Формат — [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/), номер версии — MAJOR.MINOR.PATCH по правилам [docs/build.md](docs/build.md).
```

Раздел версии идёт сразу после шапки, над прежними версиями:

```markdown
## [1.1.0] — 2026-09-29

### Добавлено
- ...

### Изменено
- ...

### Исправлено
- ...

### Удалено
- ...
```

Правила:
- Для записи без версии заголовок раздела — `## [Не выпущено]`. Он всегда стоит самым верхним. При новой версии всё содержимое раздела «Не выпущено» переносится в раздел версии, и «Не выпущено» удаляется.
- Дата — сегодняшняя, в формате ГГГГ-ММ-ДД.
- Пустые подразделы не писать.
- Писать для игрока, по-русски: что он увидит или заметит. Не упоминать модули, функции и тесты.
- Несовместимость отмечать явно. Например: «**Внимание:** прежняя таблица рекордов после обновления не читается и начинается пустой».
- Одна строка на изменение. Мелочи одного изменения объединять.

### Новый номер версии

1. Заменить `__version__` в `tetris_ui/__init__.py`.
2. Пересобрать ресурс версии без сборки exe:
   ```bash
   .venv/Scripts/python.exe -c "import build_exe; build_exe.write_version_file()"
   ```
3. Найти прежний номер: `grep -rn "<старая версия>"` по `*.py`, `*.md` и `*.yaml`, без `.venv`, `build`, `dist` и `openspec/changes/archive`. Заменить только упоминания **текущей** версии, а примеры с фиксированным номером оставить. На сейчас это:
   - `tests/test_version.py`: `test_current_version`. Тесты `version_info_text("1.0.0")` — пример формата, их не трогать;
   - `tests/test_input.py`: надписи `"v<версия>"` главного меню;
   - `openspec/specs/game-version/spec.md`: «Текущая версия», «сейчас …» и сценарии с надписью главного меню и свойствами exe. Сценарий «WHEN номер версии — 1.0.0» — пример, его не трогать;
   - `openspec/config.yaml`: «сейчас …» в разделе «Реализовано»;
   - `docs/build.md`: «сейчас …» и надпись «v…» в разделе «Версия». Примеры переходов (1.0.0 → 1.0.1) не трогать.

   Правка спецификации `game-version` здесь — синхронизация текущего номера, а не новое поведение. Отдельное OpenSpec-изменение для неё не нужно.
4. Проверить:
   ```bash
   .venv/Scripts/python.exe -m pytest tests/test_version.py tests/test_input.py tests/test_docs.py tests/test_build.py -q
   ```
   Затем `openspec validate game-version --type spec --strict`. Если что-то упало, починить и не отчитываться, пока не пройдёт.

## 5. Отчёт

Коротко перечислить:
- новую версию или «без версии»;
- что записано в `CHANGELOG.md`;
- какие файлы изменены;
- результат тестов.

Не коммитить, если игрок не просил. Если поднята версия, напомнить: `version_info.txt` коммитится вместе с `tetris_ui/__init__.py`.
